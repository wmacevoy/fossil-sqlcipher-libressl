# fossil-see build patches

Small patches applied to the upstream Fossil source tree during the build. Each is self-contained, attributed to a specific Fossil revision (`FOSSIL_REF` in `../versions.env`), and small enough to read in one sitting.

## Patches in this directory

- **`fossil-db-key.patch`** — wires a mode-aware key source into Fossil's existing SEE scaffolding (`db_maybe_obtain_encryption_key` in `src/db.c`). Priority: `FOSSIL_SEE_KEY` env var (testing-only escape hatch) → gpg-decrypted `<repo-dir>/keys/master.key.asc` → Fossil's stock interactive prompt, only if `FOSSIL_SEE_STOCK_PROMPT=1`. Fails fast with a descriptive `fossil_fatal()` if none produce a key. See `../../docs/SECURITY.md` for the full design.

- **`fossil-server-key-validator.patch`** — fixes `fossil server`/`fossil ui` on SEE/SQLCipher builds. Server startup (`db_setup_for_saved_encryption_key()`) pre-allocates a zeroed mlock'd page for the key so forked request children can inherit it; `db_maybe_obtain_encryption_key()` checked only that the saved-key pointer was non-NULL, mistook the zero page for a real key, skipped every key source above, and every repo open failed `SQLITE_NOTADB`. Fix consults Fossil's own `db_have_saved_encryption_key()` validator. Apply after `fossil-db-key.patch`. Stock Fossil (verified 2.28, 2.29) has the identical unvalidated check — see `../../docs/upstream-report-fossil-server-see-key.md` (drafted, not yet filed with fossil-scm.org).

- **`fossil-db-embed.patch`** — adds `db_clear_delete_on_failure()`, exposing one new function; changes no existing behavior. Needed for any future in-process/embedded use (repeated `fossil_main()` calls in one process must clear stale delete-on-failure registrations between calls, or a later failure deletes files created by an earlier successful command — including the repository itself). See `../../embed/README.md`.

- **`fossil-embed-exit-trap.patch`** — adds `fossil_embed_init()` (registers a handler `fossil_exit()` calls instead of libc `exit()`, for in-process/FFI embeddings with no fork/exec available, e.g. iOS); routes `fossil_fatal()`'s reentrancy-guard bypass and `content.c`'s `test-integrity --db-only`/`--quick` check through `fossil_exit()` instead of raw `exit()`. Also adds `fossil_reset_fatal_guard()`: without it, `fossil_fatal()`'s reentrancy guard (promoted from a function-local `static int once` to file scope) silently suppresses the error *message* — not just the exit-trap notification — for every fatal error after the first one in a process's lifetime; embedding shims must call it after every command (see `../../embed/README.md`'s "Required shim rules"). Also adds `fossil_reset_repository_filename_cache()`: fixes the cross-repo state bug, where `db_repository_filename()`'s function-local `static char *zRepo` (promoted to file scope) silently kept returning the FIRST repository ever opened in the process, corrupting later commands against a second in-process-opened repository; embedding shims must call this too, after every command. Deliberately does **not** touch `fossil_panic()`'s `abort()` path (documented as an intentional, accepted v1 gap, not an oversight — see the comment at its call site and `../../embed/README.md`). No effect on stock CLI behavior (handlers/guards default to unset/untripped). See `../../embed/README.md`.

- **`fossil-json-finfo-deletions.patch`** — fixes a real upstream Fossil bug, not a fossil-see need: `/json/finfo` silently omits every file deletion. `json_finfo.c` computes `(mlink.fid==0) AS isDel` and feeds it to `json_artifact_status_to_string()` (which can return `"removed"`), but the same query inner-joins `blob b` on `b.rid=mlink.fid` — and a deletion has `fid==0` while no blob has `rid==0`, so the join drops exactly the rows `isDel` exists to flag. The column is dead code and `"removed"` is unreachable; `isDel` was added twenty days *after* the join that defeats it, in 2012, and has never worked. The CLI `fossil finfo` is unaffected (`finfo.c` has an explicit `mlink.fid>0 OR NOT EXISTS(...)` clause), so the two faces disagree about the history of the same file. Fix is `LEFT JOIN blob b ON b.rid=mlink.fid`. Verified before/after against the pinned `FOSSIL_REF` on a repo with one file added, modified and removed. Still present on upstream trunk — see `../../docs/upstream-report-fossil-json-finfo-deletions.md` (drafted, not yet filed with fossil-scm.org).

## Conventions

- One patch per concern. Don't bundle unrelated edits.
- Patches are unified diffs (`diff -u` or `git diff` output), applied with `patch -p1` from the Fossil source root.
- Verify against the pinned `FOSSIL_REF` before treating a patch as ready.
